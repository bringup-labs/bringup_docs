# Bringup Documentation

The official documentation site for [Bringup](https://github.com/bringup-labs), built with [Docusaurus 3](https://docusaurus.io/). Published at [docs.bringup.dev](https://docs.bringup.dev).

## Prerequisites

- [Node.js](https://nodejs.org/) >= 22
- [pnpm](https://pnpm.io/) (enabled via Corepack)

```bash
corepack enable
```

## Getting Started

Install dependencies:

```bash
pnpm install
```

Start the development server:

```bash
pnpm start
```

The site will be available at `http://localhost:3000` with hot reload.

## Build

Generate a production build:

```bash
pnpm build
```

Preview the production build locally:

```bash
pnpm serve
```

## Docker

Build and run the docs site in a container:

```bash
docker build -t bringup-docs .
docker run -p 8080:80 bringup-docs
```

The site will be available at `http://localhost:8080`.

## Project Structure

```
bringup_docs/
├── docs/                      # All site content, served at /
│   ├── index.mdx              # Overview (the front page)
│   ├── get-started/           # Install → daemon → sign in → first device
│   ├── tutorials/             # Task walkthroughs
│   ├── extensions/            # One page per extension
│   │   └── bag-master/
│   │       └── flow-reference/  # Flow YAML reference
│   ├── reference/             # CLI, file locations, updates, daemon
│   ├── faq.md
│   └── assets/screenshots/    # Generated app screenshots
├── website/
│   ├── src/                   # Custom components and styles
│   ├── static/                # Static assets
│   ├── docusaurus.config.ts
│   ├── sidebars.ts
│   └── nginx.conf
├── specs/                     # Design docs (not published)
├── plans/                     # Implementation plans (not published)
├── Dockerfile
├── pnpm-workspace.yaml
└── package.json
```

Everything under `docs/` is published — `routeBasePath` is `/` and the sidebar is
autogenerated, so **directory layout is navigation**. `_category_.json` files set each
section's label and position. Design and planning documents live in `specs/` and `plans/`
precisely so they stay off the public site.

## Writing Documentation

1. Create a Markdown file in the appropriate directory under `docs/`
2. Add frontmatter:
   ```markdown
   ---
   title: Page Title
   sidebar_position: 3
   description: One line describing the page.
   ---
   ```
3. That's it — the sidebar is autogenerated from the directory tree. Do **not** edit
   `sidebars.ts`. To add or reorder a section, create or edit its `_category_.json`.

Broken links fail the build (`onBrokenLinks: 'throw'`), so run `pnpm build` before
opening a pull request.

## Screenshots

The images under `docs/assets/screenshots/` are generated by driving the real desktop
app — none are mockups. The generator lives in the app repo, not here:

```bash
npx playwright test e2e/screenshots.spec.ts
```

Run it from `bringup_desktop_app` (branch `docs/screenshot-spec`); it writes PNGs
directly into this repo. Re-run it when the UI changes.

### Supported Features

- Code blocks with syntax highlighting
- Admonitions (notes, warnings, tips, caution)
- Mermaid diagrams
- Tabs for multi-language examples

See the [Docusaurus docs](https://docusaurus.io/docs/markdown-features) for the full feature set.

## Versioning

To create a new documentation version:

```bash
pnpm docusaurus docs:version <version>
```
